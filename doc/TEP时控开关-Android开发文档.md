## 1. 项目目标与范围

### 1.1 目标

开发一个 Android App,通过 BLE 完全本地控制时控开关设备,替代原厂小程序,功能覆盖:

- 扫描发现设备并识别型号
- 连接 / 握手 / 对时 / 断线重连
- 主控:通断状态展示、工作模式切换(手动开关 UI 入口 V1 移除,仅保留协议封装)
- 定时组:增删改查与下发(支持 3 个固件族)
- 倒计时:精确到秒的一次性倒计时

### 1.2 范围界定

| 在范围内(V1) | 不在范围内(V1 之后) |
|---|---|
| 扫描 + 单设备连接(记住上次设备自动重连) | 多设备管理 / 设备列表收藏 |
| 总开关 / 单通道开关 / 输出状态 | 童锁 / 上电状态 / 按键密码 |
| 工作模式:常关/常开/自动/倒计时/循环 | 半秒定时(多数型号不支持,不默认暴露) |
| 定时组(最多 28+ 组,按型号上限) | 循环定时编辑、日出日落定位 |
| 倒计时(秒级,3232) | 计量与保护(电参/阈值/用电记录,仅计量型号) |
| 自动对时(每次连接发 5001) | 云端 / 账号 / 遥控面板图片 |

> 计量(§10)、密码(§6.3)、童锁等协议能力 **协议层先预留接口**,UI 按「收到回包才显示」原则在后续版本开放。

### 1.3 用户场景(主流程)

```
打开 App → 扫描 → 设备列表(型号 + 显示识别码 + RSSI)→ 点击连接
  → 自动握手(5011/5001/3004)→ 进入控制页
  → 开/关设备、切模式、管理定时组、设倒计时
  → 断线自动重连,重连后补 3004 校准界面
```

## 2. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 语言 | Kotlin(1.9+) | Android 官方首选,协程适合串行指令队列 |
| UI | Jetpack Compose + Material 3 | 声式 UI,状态驱动,与 ViewModel/Flow 天然契合 |

| BLE | 原生 `android.bluetooth` API(封装为 Flow) | 协议对时序敏感,原生可控;不引入第三方 BLE 库 |

| JDK / AGP | JDK 17,AGP 8.x,Gradle 8.x | Compose 要求;构建用 Gradle Wrapper |
| 依赖库 | 仅 lifecycle/viewmodel-compose、activity-compose、kotlinx-coroutines | 保持最小依赖,不引入 RxJava/Retrofit(不需要网络) |

### 3.3 数据流

```
UI 事件 → ViewModel → Repository 业务方法 → Protocol 组帧 → BleConnection 写队列 → 设备
                                                                        ↓
UI ← StateFlow<DeviceState> ← StatusParser ← FrameCodec ← 通知特征(3005/5012/…)
```

**关键原则:**

1. **设备状态单一数据源**:3005 解析结果整体替换 `DeviceState`,UI 无本地业务状态(编辑草稿除外)。
2. **指令串行**:所有下发进入写队列,逐条执行(条间隔 ≥ 100ms),避免并发写。
3. **下发后校准**:任何写指令后可选补发 `3004`,以设备回传为最终事实。

## 4. BLE 通信层设计

### 4.1 扫描与识别

- 使用 `BluetoothLeScanner`,`ScanFilter` 无法按厂商数据偏移过滤,故 **代码过滤**:解析 `ScanRecord.getManufacturerSpecificData()`,取 `companyId` 任意键下的数据数组按协议说明书 §3.1 校验:
  - `data[0..1] == 0x49 0x51`(type=4951;同时兼容 4957 时控商照)
  - `data[2] == 0x41`(encode)
  - `data[3..8]` = MAC(展示与校验)
  - `data[9..]` ASCII = productId → 查 `ModelTable` 得型号名、固件族、定时组上限
- 计算**显示识别码**:MAC 末 4 个 hex 字符 → 十进制 → 长度 ≥5 取末 4 位,否则左补 0 到 4 位(协议 §3.2)。
- 列表项展示:`型号名 + 显示识别码 + productId + RSSI`。
- **连接前必须停止扫描**(协议 §4.1 步骤②)。

### 4.2 连接时序(严格按协议 §4.1)

```
stopScan
connectGatt (autoConnect=false),超时 5s,失败重试 ≤5 次
  ↓ onConnectionStateChange=CONNECTED
discoverServices → 找短 UUID "9AF4" 服务(未命中退化为同时含 write+notify 的服务)
  ↓
写特征 = 服务内首个 properties.write(WRITE_TYPE_DEFAULT,即 Write With Response)
通知特征 = 服务内首个 notify|indicate → setCharacteristicNotification + 写 CCCD(0x2902)=0100
  ↓
requestMtu(185)  ← 必须,定时表单包可达 200+ 字节
  ↓ 等 500ms(链路就绪)
send 5011 → 等 100ms → send 5001(14B ASCII 时间 YYYYMMDDHHMMSS)
  ↓ 收 5012(productId+版本,修正族)
等 500ms → send 3004 → 收 3005 → 渲染界面
```

**每次连接都发 5001 对时**(不要只在首次),定时靠设备 RTC 执行。

### 4.3 写队列

| 规则 | 说明 |
|---|---|
| 串行 | 一条指令的 write 完成回调后才发下一条 |
| 分片 | 帧总长 > (MTU-3) 时按 MTU-3 分片,每片一次 write,片间隔 ≥ 20ms |
| 指令间隔 | 非 5001 的连续指令间 ≥ 100ms;定时表分包间隔 100ms |
| 重试 | 单包写失败重试 2 次,仍失败断开重连 |
| 超时 | 单条指令等待 write 回调超时 3s 视为失败 |

### 4.4 收包状态机(改进版,修复原实现缺陷)

原实现不处理「一包两帧」和「帧头错位」(协议 §5.2 已知缺陷)。App 实现要求:

```
缓冲区 buffer:append(新数据)
循环:
  1. 在 buffer 中搜索 fe01;之前字节全部丢弃(对齐)
  2. 无 fe01 → 清空 buffer,break
  3. buffer 长度 < 4+LEN → 等待后续数据,break
  4. 取出 [0, 4+LEN) 整帧 → 交解析 → 从 buffer 移除,继续循环
```

解析入口:`CMD = frame[4..6]`,`ARG = frame[6..]`(LEN 语义见协议 §5.1)。

### 4.5 断线与重连

- 意外断开:指数退避自动重连(1s/2s/4s/8s/15s 封顶,最多 5 次),重连成功后重新完整握手 + `3004`。
- 用户手动断开:停止重连。
- 设备断电/超距:定时与输出状态保存在设备 Flash,无需 App 侧恢复。

## 5. 协议层设计

### 5.1 组帧

```kotlin
fun frame(cmd: UShort, arg: ByteArray): ByteArray {
    // FE 01 | LEN(2B 大端 = 2 + arg.size) | CMD(2B) | ARG
}
```

时间字段一律 **ASCII 数字**(如 "08:30" → `30 38 33 30`),不是 BCD、不是时间戳。

### 5.2 指令封装(V1 必备)

| 业务方法 | 指令 | 参数要点 |
|---|---|---|
| `queryDeviceInfo()` | `5011` | 无参,等 5012 |
| `syncClock()` | `5001` | 14B ASCII `yyyyMMddHHmmss` |
| `queryStatus()` | `3004` | 无参,等 3005 |
| `setPower(ch, on)` | `3221` | `channel(1B) + state(1B)`;**以 3221 为主入口** |
| `setAllPower(on)` | `3225` | `01/00`,兜底入口(单通道机型两处都发) |
| `setMode(mode)` | `3007` | `00 常关/01 常开/02 自动/03 倒计时/04 循环/05 日落/06 半秒`(V1 用 00–04) |
| `writeTimers(list)` | `3231/3234/3236` | 按族选择,见 §5.3 |
| `clearTimers()` | 同上 | 组数=0,载荷仅一个 `00` 字节 |
| `setCountdown(h,m,s,event)` | `3232` | TLV,见协议 §8.1;设完需 `setMode(3)` |
| `keepAlive()` | `0007` | 可选保活 |

### 5.3 定时组 Codec(核心)

**单组结构**(以 3234/3236 为例,19 字节):

| 偏移 | 字段 | 长度 | 说明 |
|---|---|---|---|
| 0 | LEN | 1 | `0x13`=19,**含自身**(3231 为 `0x0F`=15) |
| 1 | IDX | 1 | 00 起连续编号 |
| 2 | EN | 1 | 仅 BATCH 族有效;GROUP 族恒发 01 |
| 3 | SWID | 1 | 通道号,单路恒 00 |
| 4 | WEEK_S | 1 | bit0=周一 … bit6=周日 |
| 5-10 | SH SM SS | 6 | ASCII 两位各 2B(3231 无 SS,占位 4B) |
| 11 | WEEK_E | 1 | 单点定时与 WEEK_S 相同 |
| 12-17 | EH EM ES | 6 | 同上(3231 无 ES) |
| 18 | EVENT | 1 | 00 关 / 01 开 |

**整包** = `[组数 N] + N × [LEN][单组]`。示例报文见协议 §7.4(可直接用作单元测试向量)。

**三族下发策略**(`ModelTable.productId → Family` 决定):

| 族 | productId 判定 | 指令 | 分包 | 删除语义 |
|---|---|---|---|---|
| LEGACY | IS0213 / IS0214(/ IS0217) | `3231` | 单包全发(受 MTU 分片) | 整表重发;清空发 `00` |
| GROUP | 其余 26 款时控开关 | `3234` | 10 组/包,间隔 100ms | EN 无效 → 删除=移除+重排 IDX+**整表重发**;清空发 `00` |
| BATCH | DZL002 / ZJSK05 / CXHY02 / WZHF10 | `3236` | 1 组/包,间隔 100ms | **将被删组置 EN=00 后单组重发**(小程序 `deleteTimer2` 的做法:只发 `[该组]` 一个包) |

**BATCH 族删除**(小程序实证逻辑,对应协议 §7.5 的「删除陷阱」):

```
删除第 r 组: timer[r].en = false → 发送载荷仅含 timer[r] 的 3236 包(EN=00)
清空/缩减: 对设备残留的高下标组逐个补发 EN=00 占位组
```

### 5.4 3005 状态解析

按协议 §9:外层 `[条目数 N] + N × [ITEM_LEN][TYPE(2B)][VALUE]`。要点:

- 逐条解析,`ITEM_LEN == 0` 或越界立即停止本包。
- 只更新收到的条目,缺失字段保留旧值。
- V1 关注 TYPE:`3220` 通道数、`3221` 通断、`3225` 总开关、`3007` 模式、`3231/3234/3236` 定时组、`3232` 倒计时详情。
- 定时组三选一,按收到 TYPE 用对应族规则解;时间 ASCII 还原:取每字节低半字节。
- `3219` 输出状态、`3229` 童锁、`3020` 上电状态等解析先实现、UI 后续版本暴露。

### 5.5 状态模型

```kotlin
data class TimerGroup(
    val index: Int,          // IDX,0 起连续
    val enabled: Boolean,    // EN(仅 BATCH 族有效)
    val weekStart: Int,      // 位图
    val weekEnd: Int,
    val start: Hms,          // 时:分:秒(3231 族秒恒 0)
    val end: Hms,
    val event: Boolean,      // true=开 false=关
)

data class DeviceState(
    val productId: String, val family: Family, val version: String,
    val channelCount: Int, val power: List<Boolean>, val allPower: Boolean,
    val mode: Int, val timers: List<TimerGroup>,
    val countdown: Countdown?, val timerMaxCnt: Int,
)
```

## 7. Android 平台注意事项

### 7.1 权限

| Android 版本 | 权限 |
|---|---|
| API 31+(Android 12+) | `BLUETOOTH_SCAN`(建议 `neverForLocation`)、`BLUETOOTH_CONNECT` 运行时申请 |
| API 24–30 | `BLUETOOTH`、`BLUETOOTH_ADMIN`(install)、`ACCESS_FINE_LOCATION`(运行时,扫描必需) |
| 通用 | 若用 `neverForLocation` 且不申定位,可免定位权限(Android 12+);低版本扫描仍需定位服务开启 |

清单中 `android:usesPermissionFlags="neverForLocation"` 于 `BLUETOOTH_SCAN`,`maxSdkVersion="30"` 于旧蓝牙权限。

### 7.2 BLE 要点

- **MTU**:连接后立即 `requestMtu(185)`,以 `onMtuChanged` 返回值为准做分片;失败回退 23 并强制分片。
- **写类型**:`WRITE_TYPE_DEFAULT`(Write With Response),逐包等 `onCharacteristicWrite`。
- **通知**:`setCharacteristicNotification(true)` **并** 写 CCCD `0x2902 = {0x01,0x00}`(部分机型只做前者不生效)。
- **主线程限制**:GATT 回调在 Binder 线程,`BluetoothGatt` 操作需切回单线程调度器串行(自建 `GattDispatcher`)。
- **厂商数据解析**:`ScanRecord` 拿不到 0xFF 时降级解析 `bytes` 原始广播(偏移计算)。
- **64 位 MAC**:Android 7+ `BluetoothDevice.address` 对非绑定设备返回 `02:00:00:00:00:00`,以广播包里的 MAC(§3.1 字节 3–8)为准。
- **兼容性**:部分机型(尤其国产 ROM)后台扫描限制,前台 Service 不在 V1,V1 仅前台运行。

### 7.3 构建环境(本机已确认)

| 项 | 状态 |
|---|---|
| Android SDK | ✅ `D:\Program\Android SDK`(platforms 28–35,build-tools 30–36,platform-tools 有 adb) |
| JDK | ⚠️ 现有 JDK 8 / 11(AS 自带);**AGP 8.x + Compose 需 JDK 17**,开发前需安装(如 Temurin 17)并在 `gradle.properties` 配 `org.gradle.java.home` 或升级 Android Studio |
| Gradle | 用 Wrapper(8.x)自动拉取,无需全局安装 |
| 真机 | BLE 调试必须真机(模拟器无蓝牙) |
